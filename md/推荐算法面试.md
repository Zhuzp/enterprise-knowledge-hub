# 推荐算法优化岗 · 面试讲法

岗位原文是浏览器信息流：召回、粗排、精排、重排、多样性、冷启动，再加上文本/视觉大模型做内容理解和生成式推荐。面试官要听的是漏斗每一层在优化什么、大模型放在哪一层、指标为什么不能只看 CTR。

你已经落地的是企业知识库里的检索漏斗：BM25 + pgvector 各召回 20 → RRF（k=60）融到 10 → qwen3-rerank 精排到 5，图谱作为第三条召回，Langfuse 记 `bm25_ids / vector_ids / rerank_ids`，离线用 chunk 命中算 recall@K。视频走分片、关键帧画面理解和 ASR。这些是「查询驱动的小规模排序」，可以直接讲。浏览器信息流的双塔、多目标精排、亿级候选和在线 A/B，按业界方案讲，不要编 CTR 提升数字。

---

## 60 秒怎么讲

信息流推荐是一条漏斗。召回从全库拿出几千条候选，粗排用轻量模型打到几百条，精排用行为序列和多目标打分打到几十条，重排再做多样性、打散和业务规则，最后出一屏。大模型不进在线打分主路径。它离线做内容理解：抽标签、打质量分、出多模态向量，写进特征，给双塔和精排用。生成式推荐我把它当成多一路召回：用语义 ID 生成下一跳内容，再交回同一套粗排精排，解决冷启动和兴趣收窄。效果看 CTR、时长、留存和负反馈，离线 AUC 涨了还要上用户级 A/B。

我自己做过的是同一条漏斗的检索版本：多路召回、排名融合、Cross-Encoder 重排、多模态解析成可向量化的文本、以及带标准答案的 recall@K。在线亿级排序和留存实验我还没在浏览器场景跑过。

## 和知识库项目的对应

| 信息流 | 你项目里已经有的 | 面试时补上的差别 |
|---|---|---|
| 多路召回 | ES BM25、pgvector、Neo4j 1～2 跳 | 还要协同过滤 i2i、双塔 ANN、热门、探索通道 |
| 融合 | RRF，因为 BM25 分和余弦分不能相加 | 召回通道之间同样只融合排名或进同一粗排模型 |
| 粗排 | 没有单独粗排；召回 top20 直接融合 | 候选上万时，先用点积/小 MLP 砍到几百，精排才吃得消 |
| 精排 | qwen3-rerank，query 和 chunk 拼在一起打分 | 信息流是用户行为序列 × 候选 item，多目标头 |
| 重排 | 取 top5 进 prompt | 一屏列表要打散作者/类目，控制探索位 |
| 内容理解 | OCR、视频关键帧 VL、ASR → Markdown → embedding | 产出类目、质量分、低质标签，进特征库，不在请求时现算 |
| 评估 | recall@K、hit@K、Langfuse span | 还要 GAUC、校准、时长、留存、A/B 护栏 |

一句话：知识库优化的是「这条证据在不在」；信息流优化的是「这个人下一屏会不会看、会看多久、明天还来不来」。漏斗形状一样，标签、特征和延迟预算不一样。

## 1. 全链路：召回、粗排、精排、重排

### 召回

目标是高召回、可接受的精度，延迟在几十毫秒，候选从百万/千万打到几千。

几路一起跑，互为补充：

- 协同：i2i（Swing、ItemCF）、u2i。强在行为共现，新物品没有行为就召不回来。
- 双塔向量：用户塔、物品塔分开编码，物品向量离线建 ANN（HNSW / Faiss），线上只算用户向量再检索。能上大规模，是因为打分是点积，物品侧不用在请求里和用户做交叉。
- 热门 / 地域 / 类目：保底，也是冷启动的兜底。
- 内容向量：标题、正文、封面、视频理解文本的 embedding。新物品当天就能被召回。
- 生成式召回：见第 5 节，作为一路，不替换整个漏斗。

双塔训练用采样 softmax 或批内负样本。热门物品当负样本太容易，模型会偷懒学「压热门」。要用热门校正（logQ）或混合均匀负样本和曝光未点击的难负样本。

你项目里的对应讲法：pgvector 是物品侧已经落好的向量，查询向量现算，和双塔「物品离线、用户在线」是同一结构。BM25 补的是编号、专有名词，和协同路补行为、内容路补新物品是同一思路。权限过滤下推到 ES 和向量 metadata，对应信息流里地域、审核状态、已读过滤要在召回里做，不能召回完再滤到空。

### 粗排

精排一条候选要看行为序列，几百条还能扛，几千条不行。粗排用双塔点积或一个小 MLP，特征是 id embedding、少量统计量（曝光、点击、完播）、内容向量，不做目标注意力。输出几百条给精排。

粗排和精排的分数量纲不同，粗排只负责截断，最终顺序以精排为准。粗排模型可以拿精排打分做蒸馏，让截断少砍掉精排会排上去的物品。

### 精排

精排做交叉。候选物品和用户历史里每个行为算注意力，历史里和当前候选像的点击权重大。这是 DIN 的目标注意力。序列长了用 SIM：先按类目检索出相关子序列，再做注意力。兴趣随时间变，用 DIEN 这种演化结构，面试点到名字和动机即可。

多目标不要合成一个「相关性」：

- 点击：pCTR，二分类 logloss。
- 点击后的转化或互动：ESMM。直接用点击样本学 CVR，会有样本选择偏差（没点击的人根本没机会转化）。ESMM 同时学 pCTR 和 pCTCVR，pCVR = pCTCVR / pCTR，曝光样本都能参与 CTR 塔。
- 多任务抢共享参数时用 MMOE / PLE：共享专家加任务专家，减轻一个任务涨、另一个任务掉。
- 时长：点击率高不代表看完。YouTube 的做法是用观看时长给正样本加权的加权逻辑回归，或者直接回归时长。负反馈（不感兴趣、快速划走）单独一个头，融合时减掉。

融合分是业务权重，不是模型内部唯一损失：

`score = w1 * pCTR + w2 * 时长期望 + w3 * 互动 - w4 * 负反馈`

权重要用在线实验调。只拉 CTR，标题党会赢。

位置偏差：用户更容易点排在前面的。训练时位置可以当特征，预估时固定成一个默认位置，否则模型把「已经排在前面」学成「用户真的喜欢」。更干净的做法是用曝光倾向分做 IPS。面试说出这个坑即可。

你项目里的对应讲法：qwen3-rerank 是 Cross-Encoder，query 和 chunk 拼在一起，比双塔细，也贵，所以只打 RRF 之后的 10 条，最后留 5 条。这就是「召回用双编码器，精排用交叉编码器，贵的模型只看截断后的候选」。知识库的标签是人工标的 chunk id；信息流的标签是点击、时长、次日回访，并且有曝光位置偏差。

### 重排

精排是逐条打分，排出来的前 10 可能是同一作者、同一话题。重排看的是一整屏。

- MMR：下一条既要和用户相关，又要和已选内容不像。`λ * 相关性 - (1-λ) * 与已选集合的最大相似度`。λ 大偏准，λ 小偏散。
- DPP：用核矩阵的行列式衡量一个集合的多样程度，适合直接选一个子集。
- 规则打散：同一作者、同一类目不能连续出现；新内容占固定探索位；已读、已点过的过滤。
- 列表模型：把精排 top N 的特征喂给一个列表模型（如 PRM）重排。成本高于 MMR，放在最后几十条上。

多样性是约束，不是把相关性打成 0。护栏指标看类目覆盖、列表内平均距离、负反馈率。CTR 掉一点可以接受，负反馈升、次留掉就不能接受。

### 冷启动

物品冷启动：没有协同行为。用内容向量召回（标题、封面、视频理解），在重排里留探索位，用 Thompson Sampling 这类带不确定度的策略分配少量流量。行为攒到阈值后，毕业进普通精排。质量模型先滤掉低质，避免探索流量浪费在标题党上。

用户冷启动：没有行为序列，DIN 没有东西可注意。用上下文（时间、地域、机型）、群体统计、兴趣选择，加上第一刷的实时点击立刻写进短期兴趣。前几刷多探索，序列变长再交给精排。

你项目里的对应讲法：新文档没有被任何人问过，仍然能被向量和 BM25 召回，靠的是内容本身，不靠「别人问过」。这就是内容冷启动。差在信息流还要主动分配探索曝光，知识库是用户来问才检索。

## 2. 内容理解、质量分、多模态表征

在线请求里跑视觉大模型做不了全库打分。链路是离线的：

1. 文本模型读标题和正文，抽出类目、主题、实体、立场/体裁，写成结构化标签。
2. 视觉模型看封面和关键帧：画面类型、清晰度、OCR 字幕、封面和标题是否一致。
3. 质量分：低俗、标题党、图文不符、信息量。用人工抽检校准，不当成最终排序分。大模型分值没有校准，不能直接当 pCTR。
4. 表征：内容 embedding 进物品塔和内容召回。标签进精排当离散特征。质量分进过滤阈值或精排特征。

落地时把大模型输出收成 Schema（类目枚举、质量 0～1、标签列表），校验失败再试一次，温度放低。和你在 Agent 里用 responseFormat 约束结构化输出是同一件事。

你项目里可以讲的实物：

- 图片：上传 MinIO，OCR 进 Markdown，再 embedding。
- 视频：ffmpeg 分片，关键帧交给画面理解模型，音轨 ASR，按时间片写进 Markdown，再分块向量化。
- 这一步产出的是可检索文本，还没有质量枚举和低质过滤。面试时主动说：若接到信息流，会在这条解析链路后面加一层 Schema 化的类目/质量分，写入特征，而不是把视频模型挂到在线精排。

用户兴趣侧：定期用大模型把近期点击摘要成兴趣短句，再 embed 成一条查询向量，作为内容召回的一路。这和知识库里「用问题向量查 chunk」同构，只是 query 从用户当次提问换成兴趣摘要。兴趣摘要按天更新，点击序列按分钟更新，两者都要，摘要替代不了实时序列。

## 3. 大模型和传统排序怎么融合

分三层，按延迟从低到高讲：

1. 特征增强（离线，主路径）。标签、质量分、多模态向量进特征库。在线精排只读特征，不调大模型。
2. 蒸馏。用大模型或精排老师给样本打软标签，学生模型是双塔或小 MLP，放到粗排。老师贵，学生上线。
3. 在线只碰截断后的集合。Cross-Encoder 或小尺寸排序模型重排 top 10～50。70B 生成模型不做全库打分。

生成模型直接输出推荐列表有三个硬问题：物品 ID 会编造、延迟超出一刷预算、业务过滤（审核、已读、地域）不好插进解码过程。所以生成结果要约束解码到合法 ID，再进原来的粗排精排。

指标各自看什么：

- CTR：点击 / 曝光。涨了可能是标题党。
- 时长：人均观看或阅读时长，对点击后的消费。
- 留存：次日、七日回访。反馈晚，实验周期长，不能只用一天 CTR 下结论。
- 满意度：完播、点赞、分享、不感兴趣、快速划走、问卷。点击是弱满意。负反馈率作为护栏。

优化目标用多任务学习这些头，融合权重用实验定。离线损失和线上指标不是一回事，见下一节。

## 4. 评估和 A/B

离线：

- 排序：AUC 看全局区分；GAUC 按用户分组算 AUC 再按曝光加权，避免高活用户主导。
- 概率：logloss 和校准（预测 0.2 的桶，实际点击是不是大约 20%）。融合分要用校准后的概率。
- 召回：Recall@K、Hit@K。你现在的评测就是这个：金标 chunk id 和 hybrid_retrieve 的返回 id 求交，再平均。没有金标不要用「返回了几条」冒充召回率。
- 列表：NDCG、类目覆盖、ILD（列表内两两不相似度）。

离线涨了线上可能不涨：离线负样本不是真实曝光分布，没有位置偏差，也没有「模型自己改变了下一步曝光」的反馈闭环。

在线：

- 分流单位是用户，不是单次请求。同一用户进同一个桶。
- 先做 AA，确认分桶没有系统性差异。
- 主指标选一个（人均时长或满意消费），CTR、负反馈、次留、多样性当护栏。主指标显著、护栏跌破，不推全。
- 信息流有物品干扰：实验组把某篇文章推热，对照组的热门分布也会变。用户分桶消不掉这种干扰。比较两条排序策略时，可以用交错实验（interleaving）：同一用户的一屏里混排两个策略的结果，看用户更点哪边。
- 新奇效应：上线头几天时长会虚高，留存实验要覆盖完整一周。

分析实验时拆维度：新老用户、冷启动物品、头部品类。大盘 CTR 涨、新用户次留跌，结论是策略在收割老兴趣，不是能推全。

你项目里的讲法：Langfuse 上 `retrieve.hybrid` 记下三路 id，可以回答「精排砍掉的是哪一路召回的」。这是链路可观测。知识库没有用户随机分流，所以没有 A/B；若要做，分流键是 user id，主指标是有引用的回答被采纳或追问率，护栏是无答案率和延迟。

## 5. 生成式推荐、信息茧房、冷启动

业界把「LLM for Rec」落成三条，不要说成让聊天模型现场写推荐理由就算推荐算法。

语义 ID 生成式召回（TIGER 这一类）：用 RQ-VAE 把物品多模态向量压成几级离散码，像词表一样。用户行为序列变成码序列，Transformer 自回归生成下一个物品的码。解码时用合法码的前缀树约束，避免编造 ID。这一路专门补协同过滤覆盖不到的新物品和跨兴趣物品，产出候选后仍进粗排精排。

生成式排序架构（Meta HSTU 这一类）：把推荐看成序列转换，用一次序列模型替代「召回双塔 + 精排 DNN」里的一部分。动机是行为序列足够长时，生成式序列模型能吃下检索和排序。面试表态：这是排序主干的替换方向，工程上要单独的训练和serving预算，不是在现有精排旁边加一个 prompt。

语言模型当理解器：P5 这类把推荐任务写成文本到文本。适合冷启动解释、兴趣摘要、数据增强，不适合作为唯一的在线打分器。

信息茧房从哪来：协同过滤强化「点过的同类」，反馈闭环让曝光越来越窄，只优化 CTR 会加速这件事。生成式模型如果只用点击序列训练，一样会窄。它不会自动变广。

对应做法：

- 召回留一条探索通道，重排留固定探索位，用不确定度而不是纯 pCTR 选新内容。
- 多兴趣建模（MIND、ComiRec）：一个用户不只一个向量，避免一个主导兴趣吃掉全部召回。
- 训练样本里混入探索曝光，不要只用用户已经爱点的正样本。
- 护栏：类目熵、新类目曝光占比、负反馈率、次留。茧房问题看这些，不看单次 CTR。
- 内容向量召回能走出协同聚类，因为邻居是语义邻居，不是共现邻居。前提是内容表征真有区分度，所以质量过滤要先做，否则语义邻居全是标题党。

冷启动和茧房用的是同一套杠杆：内容表征负责「没有行为也能被找到」，探索流量负责「找到之后有机会被验证」，多目标护栏负责「验证时不被 CTR 带偏」。

## 追问速答

**双塔为什么能做召回，精排为什么不能提前到召回？**  
双塔打分是两个向量的点积，物品向量可离线，ANN 能搜全库。精排要候选和用户序列做交叉，每个候选的计算图不一样，不能建成一个静态 ANN 索引。

**RRF 在信息流里还用不用？**  
多路召回的分数不可比时，用排名融合或直接把各路候选交给粗排模型打分。你在知识库里用 RRF，是因为 BM25 和余弦没有统一量纲，后面又没有一个统一的粗排模型。有粗排之后，RRF 可以退化成「各路配额截断」，由粗排统一打分。k=60 的作用不变：k 小则单路第一名垄断，k 大则退化成出现次数投票。

**只把向量 topK 送给排序模型行不行？**  
向量 topK 会漏掉精确实体和刚发生的协同热点，也会把语义近但质量差的带进来。所以要多路，并且在交叉模型之前做截断。知识库里纯向量会把 6601.07 和 6601.08 搞混，BM25 靠稀有编码词补上，是同一个例子。

**粗排截断会不会误杀？**  
会。用精排分蒸馏粗排，离线看「精排 topN 里有多少还在粗排输出里」。这个通过率掉了，在线时长通常起不来。

**大模型 embedding 直接替换 ID embedding？**  
新物品用内容向量补齐，有稳定行为之后 ID embedding 仍然更强。常见是两边都留：ID 向量学协同，内容向量学泛化，精排里拼接。

**CTR 涨、时长跌，你推全吗？**  
不推。先看是不是标题党：点击涨、完播跌、不感兴趣涨。再拆新老用户。主指标若定的是时长或满意消费，CTR 只是过程量。

**A/B 要开多久？**  
点击类指标方差小，几天能看方向；留存至少覆盖一个自然周，并避开上线首日的新奇效应。AA 先过。

**生成式推荐怎么保证物品存在？**  
语义 ID 解码限制在合法前缀树里，生成后映射回物品库，再过审核和已读过滤。不过滤的生成列表不能上线。

**你没做过浏览器信息流，为什么觉得做得了？**  
我做过的是同一漏斗的证据检索：三路召回、排名融合、交叉重排、多模态进向量、带金标的 recall@K。信息流多出来的是行为序列精排、多目标、探索流量和用户级实验。这些我按结构和失败模式讲，不用没跑过的实验数字代替。

## 简历里可以写的句子

下面每句都能在知识库代码里指出来。不要改成「提升信息流 CTR」。

1. 构建混合召回链路：Elasticsearch BM25 与 pgvector 各取 top20，RRF（k=60）融合为 top10，再用 qwen3-rerank 精排为 top5；Neo4j 一到两跳作为第三路召回。
2. 将图片 OCR、视频分片、关键帧画面理解和 ASR 统一成 Markdown 再向量化，作为内容表征进入检索，而不是在查询时调用视觉模型。
3. 用 Langfuse 记录各路召回 id 和重排 id，并用标注 chunk 计算 recall@K / hit@K，比较召回和重排策略。
4. 权限过滤下推到关键词、向量和图谱召回，避免先召回再在应用层丢弃导致候选被滤空。
